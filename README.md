# Pi Web Desktop

把 `pi-web` 从「开终端 → 敲命令 → 弹浏览器」变成「双击图标就能用」的 Windows 桌面外壳：

- 自动启动本机 `pi-web` 服务，页面在**应用窗口内**打开，不再跳到浏览器
- **页签**= 一个对话，支持固定、拖动排序、重启后自动恢复；后台对话**等待回答时页签名后转圈、回答完毕未查看时显示提示点**（样式与 pi-web 侧栏一致，橙色点 = 等你确认）
- **分屏**：像 VSCode 一样分 2/3/4 个展示区域，每个区域自带页签条、页签可拖到任意一侧；单栏时界面与原来完全一致；布局重启后自动恢复
- 关窗口**最小化到托盘**，服务继续跑；手机/局域网可访问（带密码）
- **完全不修改 pi-web**：`npm i -g @agegr/pi-web@latest` 升级后重启即生效

## 现在怎么用

前置条件（只需一次）：

- Node.js **≥ 22.19**（`node -v` 检查）
- `npm i -g @agegr/pi-web@latest`

启动（打包前，两种方式任选）：

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 开发模式，改界面立刻生效（推荐你现在用这个） |
| `npm run app` | 先构建再运行，行为最接近以后打包出来的 exe |

```powershell
cd D:\person\pi-web-desktop
npm run app
```

启动过程：**直接打开主窗口**，第一屏是启动页（进度 + 实时日志）；服务就绪后，同一个窗口原地切成页签栏 + pi-web 页面。全程只有一个窗口、一个任务栏图标，也不会弹出系统浏览器。

> 启动失败或点「重启服务」时，主窗口也会切回这个启动页，可直接看日志 / 点重试。开机自启（`--hidden`）则完全不显示窗口，只进托盘。

> 打包（绿色版 exe）已按你的要求暂停；`npm run dist` 保留着，随时可出包。

### 桌面快捷方式（不弹黑框）

项目根目录已经生成好了 `Pi Web Desktop.lnk`：

- **做法**：右键它 →「发送到 → 桌面快捷方式」（或直接拖到桌面）
- 双击 = 直接启动应用：不弹终端、不弹命令框，有图标（`build/icon.ico`）
- 重复双击不会开第二个：单实例，会把已有窗口/托盘唤起
- 想重新生成（比如项目目录变了）：`npm run shortcut`；想直接放到桌面：`npm run shortcut:desktop`

说明：快捷方式直接指向**官方 `electron.exe`**（不复制、不改写 Electron 二进制）；图标由快捷方式、窗口和 AUMID 注册点共同保证。

- 双击快捷方式（或 `npm run app`）= 官方 `electron.exe` 跑 `out\main\index.js`，不弹终端；`npm run dev` 同一套图标逻辑
- 启动图标来自快捷方式的 `IconLocation`（`build/icon.ico`）；窗口 / 任务栏 / Alt+Tab 图标由代码显式设置 `build/icon.ico`（多尺寸）
- Windows 任务栏还会按 AUMID（`com.local.piweb.desktop`）去开始菜单找带同 ID 的快捷方式取图标，所以 `npm run shortcut` 会在开始菜单维护**唯一**注册点，并给三个快捷方式写入该 ID
- 托盘图标由应用自己用 `tray.png` 创建，不经过 AUMID
- 改完代码要先构建一次（`npm run build` 或 `npm run app`）；换 logo：`npm run icons` → `npm run shortcut`
- 任务栏图标不对：跑 `npm run shortcut` 后重启应用；若还固定着旧图标，取消固定再重新拖上去

## 界面说明

```
┌──────────────────────────────────────────────────────────────┐
│ [π] 对话A ×  [π] 对话B ×  +                      30141 · v0.15.0 │  ← 页签栏
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                    pi-web 页面（每个页签独立）                 │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**页签是怎么工作的**（三个问题之一）

- 一个页签 = **一个 URL**：`/?session=<id>`（具体对话）、`/?cwd=<路径>`（在某目录开新对话）、`/`（默认）
- 标题/图标直接取自页面（所以显示的是会话名或工作区名）
- **固定**只是「钉在最左 + 不能被 Ctrl+W/中键误关」，不改 URL；右键→取消固定即可恢复
- 重启后按 `tabs.json` 里的 URL 重新打开（会话被删了会提示「该会话已不存在」）
- **页签栏和顶部条会跟随 pi-web 的任意主题**（`light`/`dark` 之外的 `mist`、`pine`、`sand`、`zenburn`… 也可以）：壳子直接读取页面里实际生效的 CSS 变量（`--bg`/`--border`/`--text`/`--accent`…），不写死配色表，pi-web 以后加新主题也不用改这里（约 1 秒内同步）
- 上次主题会缓存到 `theme.json`，**从第二次启动起首帧就是正确配色**，不会再先闪一下系统明暗（只有第一次启动 / 删掉缓存后才可能看到一次）
- 窗口用**自绘标题栏**（页签栏本身就是标题栏）：Windows 原生那条永远白色的标题栏被隐藏，右上角的最小化/最大化/关闭由系统叠加绘制，底色和图标色也跟着主题变。想退回系统标题栏：设环境变量 `PI_WEB_DESKTOP_NATIVE_TITLEBAR=1`

**大输入框（长文本便签）**

- pi-web 的「发送」按钮左侧会多出一个 `⤢` 按钮（由壳子注入，不改 pi-web 文件），和发送按钮同高对齐
- 点开后**自动打开右侧文件面板，编辑器就嵌在面板内容区里**，不会遮住中间的对话；原来的文件预览被临时盖住，关掉便签即恢复
- `Ctrl+Enter` 或「发送到对话」把内容写回 pi-web 原来的输入框并发送；`Esc` 收起。若输入框已有内容，会在其后追加（空一行），不会覆盖
- 想临时关掉：设环境变量 `PI_WEB_DESKTOP_NO_COMPOSER_EXPAND=1` 后重启应用
- **兼容性**：只在运行时往页面 realm 里加浮动元素、包装 `EventSource`/`Notification`，不改 pi-web 的文件和构建产物；但依赖 4 个页面契约（`textarea.chat-input-textarea`、发送按钮的 `aria-label`、`#file-panel` / `.file-panel-expand-button`、SSE 的 `agent_end`）。`pi-web` 升级后若这些变了，最坏情况是这个按钮/状态兜底失效，不会导致 pi-web 本身打不开；跑 `npm run check:composer` 可同时检查注入脚本和本机 pi-web 的这些契约是否还在。

- **页签栏**

- 点击切换；中间滚轮/中键关闭（固定页签不会关）
- **页签名后的状态指示**（样式与 pi-web 侧栏会话列表完全一致）：
  - 转圈 = 该页签当前对话正在等待回答
  - 蓝点 = 回答完毕还没切到这个页签看过（切过去即消失，同一轮不会重复提示）
  - 橙点 = 智能体在等你确认 / 回答提问（比蓝点更急）
  - 固定页签上显示为图标右上角的小徽标；悬停页签可在 tooltip 里看到文字说明
  - **只对该页签自己 URL 里的 `?session=` 生效**：壳子按每个页签的会话独立追踪 running 状态。刻意不用 pi-web 的 `pi-web:unread-session-ids`（全局共享、会残留历史会话），也忽略 pi-web 用 canvas 画的 favicon 全局角标，避免「一个对话完成，所有页签一起亮」
  - pi-web 侧栏会话列表里的未读点是它自己的会话级状态，不属于页签提示，壳子不改动
- 右键菜单：固定页签 / 在右侧·下方分屏显示 / 移动到窗格 / 重新加载 / 复制会话链接 / 在新页签打开 / 关闭页签 / 关闭其他 / 关闭右侧
- 拖动排序（分屏时拖到别的区域即移动分组）；`▣` 分屏按钮（见[分屏](#分屏多窗格)）、`+` 按钮 / `Ctrl+T` 开新页签；页签右侧空白处是窗口拖曳条（双击 = 最大化/还原窗口）
- `+` 右边的滑块按钮 = 打开 **Pi Web Desktop 设置**（与菜单 → 文件 → 设置…、托盘菜单「设置…」是同一个窗口；「检查 pi-web 更新」也在里面）
- **固定页签**收窄成图标、永远在最左，重启后保持固定状态
- 右侧状态：`端口 · pi-web 版本`，圆点颜色表示状态
  - 绿 = 本应用拉起的服务在跑
  - 黄 = 复用了你在终端里已经跑着的实例（退出应用不会杀掉它）
  - 红 = 启动失败（点菜单「服务 → 状态」看原因）

**服务自愈**：服务意外退出会自动重拉（最多 3 次/2 分钟）；如果之前是复用你终端里的实例、而那个实例被关掉了，应用会**自动接管**并自己拉起一个（同一端口），页签自动刷新，不需要重启应用。

## 分屏（多窗格）

和 VSCode 的**编辑器组**一样：分屏就是多开几个展示区域，每个区域**自带一条页签条**，下面直接是内容区。没有全局页签栏 + 第二行窗格条那种两层结构，也没有页签上的数字徽标。

```
单栏（和没分屏时完全一样）        左右双栏（两个区域各有一条页签条）
┌────────────────────────┐   ┌──────────────┬──────────────┐
│ A × │ B × │  +  ▣  ⚙ 状态 │   │ A × │  +   │ B × │  + ▣ ⚙ │
├────────────────────────┤   ├──────────────┼──────────────┤
│                        │   │              │              │
│       pi-web A          │   │  pi-web A    │  pi-web B    │
│                        │   │              │              │
└────────────────────────┘   └──────────────┴──────────────┘
```

一个页签 = 一个独立的 `WebContentsView`，所以每个区域都是完整可操作的 pi-web 页面（不是截图、不是 iframe），两边都能打字、都能跑任务。页签**按组归属**：单栏时所有页签都在唯一的那一组里，所以界面和行为跟分屏功能加入之前一模一样。

**怎么开**

- 页签栏右侧的**分屏按钮**（▣）：下拉里选单栏 / 左右双栏 / 上下双栏 / 三栏 / 四宫格，还能「向右拆分」「关闭当前窗格」「焦点移到某窗格」
- 菜单 → **视图** → 同样的布局项
- 右键页签 →「在右侧分屏显示」/「在下方分屏显示」/「移动到窗格」
- `Alt` + 点击页签 = 把它放到右侧新窗格

**怎么摆弄页签（重点）**

- **拖动**：按住任意页签，会浮出投放区 —— 拖到哪个区域，页签就归到那一组；投放区里还会显示该组现有页签的占位，可以选插入位置。拖到窗口**最左 / 最右边缘**则直接新建一个窗格
- 如果源窗格只剩这一个页签，会自动把目标窗格当前显示的页签换回源窗格，**保证分屏不会因为一次拖动就没了**（VSCode 会直接关掉空组，这里刻意不这么做）
- 每条页签条右侧的 `+` 只在该窗格开新页签；右键空白页签条 →「把哪个页签移动到这里」/ 关窗格 / 退出分屏
- 点击页签 = 切到它所在的窗格并显示它（**不会新开窗格**）；每个窗格可以放多个页签，只有当前那个的内容区可见
- **当前窗格**靠 active 页签下方的强调色细线区分（非焦点窗格是淡线），没有额外的边框；托盘菜单里正在显示的页签带 `[1]` 前缀
- 关掉某组最后一个页签时该窗格自动消失，页签合并到相邻窗格；关到只剩 1 组就自动回到单栏（所有页签都还在）
- `Ctrl+T` / `Ctrl+W` / `Ctrl+R` / 缩放 / `F12` 只作用于当前窗格；可见的页签都算「已查看」，不会再亮未读点
- 分组写进 `tabs.json`，**重启后自动恢复**；同一个页签只属于一个组，不会同时出现在两个窗格里

> 当前版本是等分窗格，暂不支持拖动分隔条调宽度。布局公式集中在 `src/shared/split.ts` 的 `computePaneRects()` / `paneContentRect()`，主进程摆视图和界面算位置共用一份；以后加权重只需改这一处。

### 为什么 `Ctrl+数字` 保持「切页签」

VSCode 的 `Ctrl+1/2/3` 是「聚焦第 n 个编辑器组」，但本应用首先是**浏览器式页签**：`Ctrl+1…9` 一直是「跳到第 n 个页签」，改掉会破坏现有用户的肌肉记忆；而且分屏之后「跳到第 2 个页签」依然高频。因此分屏**另起一层快捷键**，不动 `Ctrl+数字`：

| 层 | 键 | 作用 |
| --- | --- | --- |
| 页签 | `Ctrl+1` … `Ctrl+9` | 切页签（分屏时：切到它所在的窗格并显示它） |
| 布局 | `Ctrl+Alt+1` … `Ctrl+Alt+4` | 单栏 / 左右双栏 / 三栏 / 四宫格 |
| 布局 | `Ctrl+\` / `Ctrl+Shift+\` | 向右拆分 / 关闭当前窗格（VSCode 原始的拆分键） |
| 窗格 | `Ctrl+Alt+←/→`（`↑/↓` 同） | 在窗格之间移动焦点 |
| 鼠标 | `Alt+点击页签` | 在右侧新窗格打开该页签 |

分屏按钮 + 右键菜单 + 每条页签条的 `+` 负责**可发现性**（不记快捷键也能用），拖动负责**自由摆放**，快捷键负责**效率**；几条路最终都调 `TabManager` 的同一组方法，行为完全一致。

## 托盘与关闭行为

- **点窗口的 ×** → 窗口隐藏，**服务继续运行**（默认）。第一次会弹一个托盘气泡提示。
- 托盘图标：单击/双击 = 显示主窗口；右键 = 菜单
  - 显示主窗口
  - 页签（点击直接切到那一页）
  - 局域网地址（点击复制）
  - 重启服务 / 设置… / 打开日志
  - **退出并停止服务**（真正退出，会杀掉本应用拉起的 pi-web）
- 想改成「关窗口就退出」：设置 → 窗口 → 关闭窗口时 → 直接退出并停止服务。

> 托盘图标在 Windows 上可能被折叠到「^」里，拖出来固定即可。

## 局域网 / 手机访问

用手机或另一台电脑打开 pi-web（沿用 pi-web 自己的 `PI_WEB_PASSWORD` 机制）：

1. 菜单 → 文件 → **设置…**
2. 勾选「允许局域网内其他设备访问」
3. 点「生成随机密码」（至少 8 位；也可自己填）
4. 点 **保存并重启服务**
5. 面板里的「在手机 / 其他电脑打开」会列出地址，例如 `http://10.225.11.112:30141` → 复制到手机浏览器打开 → 输入密码

要点：

- 密码经 **系统凭据加密**保存在 `secure.bin`，不写明文、不进日志，只通过环境变量传给 pi-web
- 开启局域网时**绝不复用**外部实例，端口被占会自动换一个（如 30142），保证对外的一定是带密码的那个 → 端口变了以设置页/托盘里显示的为准
- 密码只保护登录，**流量仍是明文 HTTP**：只在信任的局域网使用；跨网/公网请用 Tailscale / WireGuard 或 HTTPS 反代
- 关闭开关 → 保存并重启 → 服务回到只听 `127.0.0.1`，密码同时被删除

**防火墙**：本应用**不会修改你的防火墙设置**。手机连不上时，设置页里给了一条可复制的命令，要不要执行由你决定：

```
netsh advfirewall firewall add rule name="Pi Web Desktop" dir=in action=allow protocol=TCP localport=30141
```

手机连不上先自查：是否同一 Wi-Fi / 是否开了 AP 隔离 / 是否连了 VPN / Windows 网络是否被识别为「公用网络」。

## 设置项说明

菜单 → 文件 → 设置…（或托盘菜单「设置…」）

| 设置 | 说明 |
| --- | --- |
| 关闭窗口时 | 最小化到托盘（推荐）/ 直接退出并停止服务 |
| 窗口置顶 | 让窗口始终在其他窗口上面 |
| 开机自启 | 默认关闭；开启后开机直接进托盘。绿色版路径会变，此项置灰 |
| 启动时恢复上次的页签 | 关掉则每次启动只开一个空页签 |
| 端口 | 默认 30141；被占用会自动尝试 30142–30150 |
| 局域网访问 / 密码 | 见上一节 |
| 状态区 | 显示当前 pi-web 版本、node 版本、实际脚本路径、服务状态 |
| 检查 pi-web 更新 | 一键：按当前 npm registry 查新版本 → 停服务 → `npm install -g` 更新全局包 → 重启服务；下方实时显示 npm 输出 |

## 常见问题

**Q：页签栏只有黑白 / 顶部标题栏一直是白的，不跟 pi-web 主题**
旧版只认 `light`/`dark` 两个名字，且把 `localStorage["pi-theme"]` 当成 JSON 解析（实际存的是 `mist`、`pine` 这种字符串），于是所有彩色主题都被忽略，只剩内置的黑/白两套色。现在改成直接读页面 `:root` 上生效的 CSS 变量，14 个内置主题都能跟随。
顶部那条白的是 **Windows 原生标题栏**：它只跟系统明暗走，Electron 默认边框没法按网页主题任意着色。现在已隐藏并改成自绘标题栏（系统窗口控件叠加），所以它也跟着主题变。若想用回系统标题栏：设环境变量 `PI_WEB_DESKTOP_NATIVE_TITLEBAR=1` 后重启。

**Q：启动页显示「没有找到已安装的 @agegr/pi-web」**
先装：`npm i -g @agegr/pi-web@latest`，然后点启动页的「重试」。

**Q：提示需要 Node ≥ 22.19**
换 Node 版本（nvm 用户：`nvm install 22.22.1 && nvm use 22.22.1`），再「重试」。
注意必须用系统 Node：pi-web 里的 `node-pty` 是原生模块，和 Electron 自带 Node 的 ABI 不兼容。

**Q：状态是黄色、显示「复用」**
说明你已经有一个 pi-web 在跑（终端或别的方式启动的），应用直接连它、退出时**不会**杀掉它。想完全由应用托管就先 `pi-web stop`。

**Q：点「检查 pi-web 更新」提示「还有 pi-web 实例在运行」**
全局包里的 `.next/` 正被别的 pi-web 进程占用，覆盖安装可能失败或留下半更新目录（上游 `pi-web update` 也会拒绝）。
按提示在对应终端执行 `pi-web stop --port <端口>`，或托盘退出那个应用；按钮会自动把刚才停掉的服务恢复到旧版，可安全重试。

**Q：端口被占用 / 地址变成 30142**
自动回退到了下一个空闲端口（也可能是开启局域网时主动换口，避免复用无密码实例）。真实地址看页签栏右侧状态、设置页状态区或托盘菜单。

**Q：页签重启后没恢复**
检查设置里「启动时恢复上次的页签」是否被关；再看 `tabs.json` 是否还在。另外 pi-web 会校验 `?session=`，会话被删掉时该页签会提示「该会话已不存在」，属正常。

**Q：页面白屏 / 显示离线页**
服务如果挂掉，应用会自动重拉（约 1–15 秒），页签会自动刷新；通常等几秒就好。仍然不行就看菜单「服务 → 状态」和 `server.log`，或手动「服务 → 重启服务」。

**Q：对话任务完成后没有 Windows 通知？**
pi-web 完成时优先用 `ServiceWorkerRegistration.showNotification()`；实测 Electron/Windows 上这个调用会「成功返回，但 Windows 通知历史里根本没有 toast」，而 pi-web 成功后就不再回落 `new Notification()`。桌面壳在页面加载后注入一段补丁，让 SW 的 `showNotification` reject，逼 pi-web 走 `window.Notification` 分支，由 Chromium 正常弹系统通知；同时把主窗口失焦同步给页面的 `document.hasFocus()`（Electron 的 WebContentsView 失焦后仍会误报「有焦点」），保证「窗口不在前台」时和 Chrome 一样触发，不改 pi-web 文件。多项目同时跑时，补丁还会把当前页签名（页面标题）拼进通知标题（如 `sgs_web_week — 任务完成`），一眼看出是哪个项目完成了；若标题本身就是页签名则不重复。通知弹出后 Electron 会自动写 `Electron.lnk`，主进程会立刻清掉，见下一个问题。

**Q：任务栏是 Electron 原子图标，系统托盘却是对的**
多半是开始菜单里冒出了一个 `Electron.lnk`：它带本应用的 AUMID，但图标为空（回落到 electron.exe 原子图标），任务栏按 AUMID 解析到它就会覆盖窗口 icon；托盘由应用自己创建，不受影响。

原因是 Windows 上只要弹过一次 **toast 通知**，Electron 就会自动创建这个快捷方式。主进程自己的服务失败提示仍走托盘气泡，但 pi-web 的任务完成通知是页面里发的 `new Notification()`，属于 Windows toast，没法关掉。应用现在监听开始菜单目录，`Electron.lnk` 一出现就在 500ms 后清掉（另有启动清一次 + 10 秒兜底轮询），所以最多闪一下。`npm run shortcut` 还会给标准快捷方式写入固定的 `ToastActivatorCLSID`（与主进程一致），让重启后通知中心里的旧通知也能点开。若仍看到：跑一次 `npm run shortcut` 再重启应用，并确认开始菜单里没有 `Electron.lnk`；还固定着旧图标就取消固定重新拖上去。`server.log` 里 `[icon] 窗口图标：` 应为 `build/icon.ico`。

**Q：应用没反应，第二次双击没出新窗口**
本应用是单实例的，第二次启动只会把已有窗口提到前台（或从托盘唤起）。

**Q：想彻底关掉**
托盘 →「退出并停止服务」；或菜单 → 文件 → 退出。两者都会把本应用拉起的 pi-web 一起结束（复用的外部实例不会被杀）。

**Q：出现「A JavaScript error occurred in the main process」**
这是主进程异常弹框。之前的版本在重启服务时可能有此问题，已修；若还遇到，把 `server.log` 里 `[fatal]` 那段发我。

## 与 pi-web 的关系（升级、卸载）

- **零侵入**：不修改、不 fork、不 patch `@agegr/pi-web` 任何文件。壳子只做三件事：调用它的 CLI 启进程、加载它的 HTTP 地址、接管页面自己发起的 `window.open`
- **升级 pi-web**（两种方式）：

  **GUI 一键（推荐）**：设置 → 服务 →「检查 pi-web 更新」。按钮先按当前 npm 配置查最新版本；
  发现新版本就自动 **停止本应用托管的服务 → `npm install -g @agegr/pi-web@<版本>` → 重启服务**，
  设置页下方实时显示 npm 输出。已是最新则只提示，不动服务。
  - 更新期间服务会中断，页面可能短暂显示离线；完成后页签按 `tabs.json` 自动恢复。**安装过程中不要退出应用**，
    否则可能留下半更新的全局包
  - 若还有**外部** pi-web 实例在跑（终端里的 `pi-web`、或状态为黄色的复用实例），安装会被拒绝并自动把服务恢复到旧版；
    先 `pi-web stop` 再点一次，避免 Windows 上覆盖 `.next/` 导致半更新
  - 检查与安装都用同一个系统 node 自带的 npm（同一份 registry / `.npmrc` 配置），只认 `x.y.z` 稳定版
  - 任一步失败都会自动把服务拉回旧版，不会停在「没有服务」的状态

  **终端手动**：

  ```powershell
  pi-web stop            # 或托盘退出应用
  npm i -g @agegr/pi-web@latest
  ```

  然后正常启动应用 → 菜单 → 服务 → 状态，确认版本已变。菜单「服务 → 检查 pi-web 更新」是只读检查，
  显示当前版本、registry 最新版本和实际安装位置。

- **卸载壳子**：删除本项目目录 + `%APPDATA%\Pi Web Desktop\` 即可；pi-web 本身不受影响。
- 上游契约只在 3 个地方（`GET /`、`/?session=`、`window.open`）。升级后建议跑一次冒烟测试：

  ```powershell
  npm run smoke
  ```
